# 02 · 抓包分析实战（全实验室通用）

> USB 调试的第一原则：**不猜，抓包**。客户说"我的设备有时不识别"——十次有九次，抓一次包就知道是枚举哪一步出了问题。

## 1. 工具三层梯队

| 层 | 工具 | 能看到 | 成本 |
|---|---|---|---|
| 软件层 | Linux **usbmon**、Windows **USBPcap**（均配合 Wireshark） | URB/事务级：描述符、请求、数据、状态 | 免费 |
| 逻辑分析仪 | 24M+ 采样率 LA 探 D+/D- | 电气层：电平、速度、chirp | 几十~几百 USD |
| 协议分析仪 | Beagle USB 480、Ellisys、LeCroy | 全解析+总线时序+错误注入 | 千~万 USD 级 |

详细命令与配置见 [captures/README](../captures/README.md) 与各实验室 capture/ 目录。

## 2. 标准分析流程（SOP）

1. **固定变量**：同一根线、同一台主机、同一 USB 口（直插主板，先不过 hub）；
2. **抓完整插入过程**：先启动捕获，再插入设备（枚举从头开始才有意义）；
3. **对照标准序列**：复位 → GET_DESCRIPTOR(64) → SET_ADDRESS → GET_DESCRIPTOR(18) → 读配置 → SET_CONFIGURATION——任何一步缺失/重复/报错都指向特定根因（对照知识库[枚举流程](https://github.com/tangjianfang/USBTree/blob/main/10-树干-USB核心/08-枚举流程与标准请求.md)）；
4. **标注与存档**：把结论（根因+证据帧号）写进实验记录——三个月后你会感谢自己。

## 3. 常见 trace 特征速查

| 现象 | 指向 |
|---|---|
| 第一个 GET_DESCRIPTOR 无响应 | 设备没准备好/时钟错/EP0 包长错 |
| SET_ADDRESS 后主机换地址通信失败 | 固件地址切换时机 bug |
| GET_CONFIGURATION 返回长度 ≠ wTotalLength | 描述符自相矛盾 |
| 中断 IN 突然全 NAK | 固件缓冲/逻辑卡死 |
| 反复总线复位 | 设备拉挂总线（供电流超标/短路） |

完整故障树见 [70-枝干-调试测试与安全/02-枚举失败排查手册](https://github.com/tangjianfang/USBTree/blob/main/70-枝干-调试测试与安全/02-枚举失败排查手册.md)。
