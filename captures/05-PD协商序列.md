# 05 · USB PD 协商序列：消息级标注（教学样本）

> **⚠️ 诚实声明**：本文为**基于 USB PD 3.x 规范重构的消息级教学样本**（不含 BMC 位级波形），
> 不是真实 CC 线抓包。Header/PDO/RDO 的**位段定义与取值按 PD 规范**整理并实算十六进制；
> Source 能力档位、请求电流、Message ID 等为**示意值**。
> PD 跑在 CC 线的 BMC 调制上（约 300kbps），Wireshark/usbmon/USBPcap **抓不到 PD**——
> 真实报文需要 PD 分析仪（Total Phase PD Analyzer、GRL）、开源 Twinkle（Chromium OS EC）
> 或诱骗器（ZY12OGG/CH224 模块）旁路；亦可参考厂商公开样例 trace。每条消息之后
> 都有一条 GoodCRC 应答（规范要求，本文以灰色缩进行表示）。

**场景**：65W 充电器（Source/DFP）与手机（Sink/UFP）经 Type-C 线连接、
CC 电阻握手完成后，进入 PD 显式合同协商。

## 1. 消息帧结构（16 位 Header + 0~7 个 32 位对象）

```
| B15 | B14:12 | B11:9     | B8 | B7:6 | B5 | B4:0 |
| 扩展 | 对象数  | MessageID | 电源角色 | 规范版本 | 数据角色 | 消息类型 |
```

- 电源角色 B8：0=Sink, 1=Source（SOP 消息）；数据角色 B5：0=UFP, 1=DFP；
- 规范版本 B7:6：01=Rev2（PD2.0, 定长报文）, **10=Rev3（PD3.0, 变长报文）**——双方取共同版本；
- MessageID 0~7 循环，配合 GoodCRC 去重/确认；同一方向每发一条递增；
- 消息类型（控制）：1=GoodCRC, 3=Accept, 4=Reject, 6=PS_RDY, 7=Get_Source_Cap, 13=Soft_Reset；
  （数据）：1=Source_Capabilities, 2=Request, 4=Sink_Capabilities, 15=VDM。
- 线上传输为 LSB 先发 + 4b5b/BMC + CRC-32；本文全部按 16/32 位整数值展示。

## 2. 协商时序（t=0 起实算全部 Header/对象）

### 第 1 步：Source 广播能力

```text
Src→Snk  Source_Capabilities   Header = 0x51A1 = 0101000110100001b
         │ │   │ │ │ └ 类型=00001 Source_Capabilities(数据消息1)
         │ │   │ │ └── 数据角色=1 DFP
         │ │   │ └──── 版本=10 Rev3 (PD3.0)
         │ │   └────── 电源角色=1 Source
         │ └────────── MessageID=0
         └──────────── 对象数=5（后面跟 5 个 PDO）
  Snk→Src  GoodCRC      Header = 0x0081（MessageID 镜像 0; 角色/版本位实现各异, 示意值）
```

5 个 32 位 **PDO（Fixed Supply）**，逐位展开：

```text
PDO0 = 0x0F01912C = 00001111000000011001000100101100b   ← 5V/3A
       │ │││││ │ │        │ │││││└────────┘ └───────┘ └─┴── 类型 B31:30=00 Fixed
       │ │││││ │ │        │ │└┴┴┴ B24:23=0  B22:20 Peak=0 │└ B9:0  = 300 → 3.0A (10mA/LSB)
       │ │││││ │ │        │ └ B25=1 Dual-Role Data        └ B19:10 = 100 → 5.00V (50mV/LSB)
       │ │││││ │ └ B26=1 USB Comm Capable
       │ │└┴┴┴ B28:27 = USB Suspend=0, Unconstrained Power=1；B29 DRP=0；B24 Unchunked Ext=1
       └ B31:28 = 00（对象0恒为 5V 档——规范强制）
PDO1 = 0x0002D12C   9V/3A    （电压场 180=9.00V, 电流 300=3.0A, 标志位 0）
PDO2 = 0x0003C12C   12V/3A   （电压场 240）
PDO3 = 0x0004B12C   15V/3A   （电压场 300）
PDO4 = 0x00064145   20V/3.25A（电压场 400=20.00V, 电流 325=3.25A → 65W）
```

（档位数值为**示意值**——0x0F01912C 等 5 个 PDO 的十六进制是按所列位段实算的结果；
Unconstrained=1 表示"适配器功率不设限"，仅 PDO0 定义标志位。）

### 第 2 步：Sink 选档请求

手机需要 2.5A 工作电流，选择第 5 个 PDO（20V，Object Position 从 1 数起）：

```text
Snk→Src  Request       Header = 0x1082 = 0001000010000010b
         │ │   │ │ │ └ 类型=00010 Request(数据消息2)
         │ │   │ │ └── 数据角色=0 UFP
         │ │   │ └──── 版本=10 Rev3
         │ │   └────── 电源角色=0 Sink
         │ └────────── MessageID=0（各方向独立计数）
         └──────────── 对象数=1（一个 RDO）
  Src→Snk  GoodCRC      Header = 0x01A1（镜像 ID0; 角色位示意值）
```

32 位 **RDO（Fixed Supply Request）**逐位：

```text
RDO = 0x5183E945 = 01010001100000111110100101000101b
      │ │││││││              │ │││││└ B9:0  = 325 → 最大工作电流 3.25A（等于 PDO0 档上限）
      │ │││││││              │ └───── B19:10 = 250 → 本次请求工作电流 2.50A
      │ │││││││              └ B24=1 No USB Suspend（"别把我挂起", 示意策略）
      │ ││││││└ B23=1 USB Comm Capable；B25=0 Unchunked Ext；B27=0 Capability Mismatch
      │ └┴┴┴ B31:28 = 0101 = Object Position 5 → 请求 PDO4（20V 档）
      └ B26/B22 保留（B22 为 PD3.1 的 EPR Mode Capable, 本例 0）
```

> **易错点**：RDO 高 4 位是 **Object Position（1 起数）**，不是电压、也不是 EPR 模式；
> Capability Mismatch=1 表示 Source 无一档完全满足需求（诊断"能充但不满速"的关键证据）；
> EPR（28V+）不是直接 Request 可达的，要先走 EPR Mode Entry 序列。

### 第 3 步：Source 接受

```text
Src→Snk  Accept         Header = 0x03A3 = 0000001110100011b
         对象数=0 · MessageID=1（递增）· Source/DFP/Rev3 · 控制消息类型=3
  Snk→Src  GoodCRC      Header = 0x0281（镜像 ID1; 示意值）
```

（若无法满足则回 **Reject**（类型 4）或 Wait，合同维持旧档或无合同——充电器"5V 兜底"就是无合同态。）

### 第 4 步：电压就位

```text
Src→Snk  PS_RDY        Header = 0x05A6 = 0000010110100110b
         对象数=0 · MessageID=2 · 类型=6
  Snk→Src  GoodCRC      Header = 0x0481（镜像 ID2; 示意值）
```

Accept 之后 Source 才调整 VBUS（5V→20V 电压爬坡），调整完毕发 PS_RDY。
**Sink 在 PS_RDY 之前不得假设电压已切换**——两条控制消息之间可能间隔数十毫秒。

## 3. 时序总览

```text
Src                          Snk
 │ Source_Capabilities(0x51A1, 5×PDO) ─▶
 │                             ◀─ GoodCRC(0x0081)
 │                             ◀─ Request(0x1082, RDO=0x5183E945)
 │ GoodCRC(0x01A1) ─▶         │
 │ Accept(0x03A3) ─▶          │   ← 合同达成, 开始调压
 │                             ◀─ GoodCRC(0x0281)
 │ PS_RDY(0x05A6) ─▶          │   ← 20V 就位, Sink 可满速取电
 │                             ◀─ GoodCRC(0x0481)
```

后续机制速记：

- Sink 需求变化（如亮屏）→ 再次 Request，同一舞步重跳；
- Source 能力变化 → 重新广播 Source_Capabilities（ID 继续循环 0~7）；
- 协议僵死 → Soft_Reset（控制消息 13）；彻底死锁 → Hard Reset（无消息可发，VBUS 掉到 vSafe0V 再回 5V，设备可能重启会话）；
- 角色反转三件套：PR_Swap（供电方向）/ DR_Swap（数据角色）/ VCONN_Swap（给 E-marker 线供电），均为控制消息交换 + PS_RDY 确认。

## 4. 实测 PD 的工具梯队

| 工具 | 类型 | 能看到 |
|---|---|---|
| Total Phase USB PD Analyzer / GRL | 商用分析仪 | CC 线全报文解码 + VBUS 电流曲线 |
| **Twinkie**（Chromium OS EC 开源） | 旁路抓包器 | SOP 报文在线解码 |
| ZY12OGG / CH224 模块 | 诱骗/触发器 | 模拟 Sink 请求指定 PDO，验证充电器真实档位（如"标称 65W 是否真给 20V/3.25A"） |
| FNB58 / UM34 等电压电流表 | 仪表 | 数值佐证，无协议解码 |
