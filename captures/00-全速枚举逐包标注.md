# 00 · 全速枚举逐包标注（教学样本）

> **⚠️ 诚实声明**：本文的包序列是**基于 USB 2.0 规范重构的教学样本**，不是真实抓包。
> 所有 token 的 CRC5 与 data 的 CRC16 均按规范算法（§8.3.5）对文中负载**实算**（生成与校验脚本
> [`../tools/_usbcalc.py`](../tools/_usbcalc.py)，内嵌规范余数 01100B / 1000000000001101B 断言），
> 但**时序、帧号、设备身份（VID/PID/字符串）为示意值**。
> 真实抓包获取：① Wireshark 样例捕获页 <https://wiki.wireshark.org/SampleCaptures>；
> ② 自己用 usbmon/USBPcap 抓（命令见本目录 [README](README.md) 与 [`../tools/usbmon_howto.md`](../tools/usbmon_howto.md)）；
> ③ USB-IF 合规测试 trace。usbmon 抓到的是 URB 级，看不到本文的线级 token/握手——那需要硬件分析仪。

**样本设备**：全速（FS）双协议鼠标，插入根集线器端口（无前置 PRE，LS 才需要）。
复位、Chirp 握手、挂起/恢复电气事件不属于包序列，用注释行表示。

## 0. 包格式速查（后文标注的基础）

```
Token 包   : [SYNC] PID(8) ADDR(7) ENDP(4) CRC5(5) [EOP]   ← 3 字节（PID+2）
Data 包    : [SYNC] PID(8) PAYLOAD(N) CRC16(2) [EOP]       ← N+3 字节
Handshake  : [SYNC] PID(8) [EOP]                           ← 1 字节
```

多字节字段线上**按位 LSB 先发**；CRC 按规范"取反后 MSb 先发"，折回字节流后的两个 CRC 字节
=（余数高字节位反转）、（余数低字节位反转）。token 的 2 个字节打包规律：
byte0 低 7 位=ADDR、bit7=ENDP 的 bit0；byte1 低 3 位=ENDP 的 bit1~3。

| PID | 字节 | 说明 |
|---|---|---|
| OUT | `E1` | 主机→设备 |
| IN | `69` | 设备→主机 |
| SETUP | `2D` | 控制传输第一拍，只发端点 0 |
| SOF | `A5` | 每 1ms 一发，ADDR 位置放 11 位帧号 |
| DATA0 | `C3` | 数据 PID（Setup 阶段恒用） |
| DATA1 | `4B` | 数据 PID（toggle 交替） |
| ACK | `D2` | 收到且校验通过 |
| NAK | `5A` | 忙/暂无，不是错误 |

## 1. 插入与复位

```text
[电气事件] D+ 上拉 → 集线器报告端口连接 → 主机发端口复位（SE0 ≥ 10ms）→ 设备以 FS 挂上总线
[说明]     设备此时地址 = 0（默认地址），只有端点 0 可用
```

总线每 1ms 有一个 SOF（帧号 0~2047 循环）。线上是这根心跳让设备校准位采样：

```text
[SYNC] A5 64 F8      ; SOF, 帧号=100 (0x064)。CRC5 覆盖 11 位帧号
[SYNC] A5 65 00      ; SOF, 帧号=101 (0x065)
…                    ; 帧号递增（本文帧号均为示意值）
```

## 2. 事务一：GET_DESCRIPTOR(Device)，wLength=64

主机故意要 64 字节——**顺带探测 bMaxPacketSize0**（设备只会回 18 字节，短包结束数据阶段）。

### 2.1 Token

```text
[SYNC] 2D 00 10      ; SETUP, ADDR=0, ENDP=0, CRC5=0x08(取反余数, 实算)
         │  └┴─ ADDR+ENDP+CRC5 打包字节（ADDR=0, ENDP=0）
         └─ PID=SETUP
```

### 2.2 SETUP 数据（8 字节请求，恒 DATA0）

```text
[SYNC] C3 80 06 00 01 00 00 40 00 DD 94
       │  │  │  ─┬─ │  │  ─┬─ ─┬─
       │  │  │   │  │  │   │  └─ CRC16 = DD 94（实算, 低反射字节在前）
       │  │  │   │  │  │   └──── wLength = 0x0040 = 64（小端）
       │  │  │   │  │  └──────── wIndex  = 0x0000
       │  │  │   │  └─────────── wValue  = 0x0100：高字节=描述符类型 0x01(设备), 低字节=索引 0
       │  │  │   └────────────── bRequest = 0x06 GET_DESCRIPTOR
       │  │  └────────────────── bmRequestType = 0x80: D7=1(IN) D6~5=00(标准) D4~0=00000(设备)
       │  └───────────────────── PID = DATA0（Setup 阶段恒为 DATA0）
       └──────────────────────── PID = DATA0 → C3
```

```text
[SYNC] D2            ; 设备 ACK（SETUP 必须接受，不允许 NAK 到卡死）
```

### 2.3 数据阶段：设备回 18 字节设备描述符

```text
[SYNC] 69 00 10      ; IN, ADDR=0, ENDP=0（CRC5 实算）
[SYNC] 4B 12 01 00 02 00 00 00 40 41 23 01 00 00 01 01 02 00 01 EE E6
       │  └───────────── 18 字节负载（逐字段见下）─────────────┘ │  │
       │                                                       └ CRC16=EE E6(实算)
       └ DATA1（控制数据阶段以 DATA1 起步）
[SYNC] D2            ; 主机 ACK
```

18 字节设备描述符逐字段（自洽样例）：

| 字节 | 值 | 字段 | 解释 |
|---|---|---|---|
| 0 | `12` | bLength | 18 字节（描述符首字节永远是长度） |
| 1 | `01` | bDescriptorType | 设备描述符 |
| 2~3 | `00 02` | bcdUSB | USB 2.00（BCD，小端） |
| 4 | `00` | bDeviceClass | 类在接口级声明（HID 类设备标准做法） |
| 5 | `00` | bDeviceSubClass | — |
| 6 | `00` | bDeviceProtocol | — |
| 7 | `40` | bMaxPacketSize0 | 端点 0 最大包 = 64 字节 |
| 8~9 | `41 23` | idVendor | 0x2341（**示意值**，勿用于真实产品） |
| 10~11 | `01 00` | idProduct | 0x0001（**示意值**） |
| 12~13 | `00 01` | bcdDevice | 版本 1.00（**示意值**） |
| 14 | `01` | iManufacturer | 厂商串 = 索引 1 |
| 15 | `02` | iProduct | 产品串 = 索引 2 |
| 16 | `00` | iSerialNumber | 无序列号 |
| 17 | `01` | bNumConfigurations | 1 个配置（与后文一致） |

说明：负载 18 字节 < 主机要的 64 → **短包（<64）天然标志数据阶段结束**，主机不再收，
直接转入状态阶段：

```text
[SYNC] E1 00 10      ; OUT, ADDR=0, ENDP=0（状态阶段方向反转：主机收→发）
[SYNC] 4B 00 00      ; 设备回 DATA1 零长度包（ZLP = "明白，成功"）
[SYNC] D2            ; 主机 ACK。控制读状态阶段恒为 DATA1 ZLP
```

## 3. 事务二：SET_ADDRESS(5)

```text
[SYNC] 2D 00 10      ; SETUP, 仍用地址 0
[SYNC] C3 00 05 05 00 00 00 00 00 EA A1
         │  │  ─┬─ │  │  ─┬─ ─┬─
         │  │   │  │  │   │  └─ CRC16 = EA A1（实算）
         │  │   │  │  │   └──── wLength = 0（无数据阶段）
         │  │   │  │  └──────── wIndex = 0
         │  │   │  └─────────── wValue = 0x0005 → 新地址 = 5
         │  │   └────────────── bRequest = 0x05 SET_ADDRESS
         │  └────────────────── bmRequestType = 0x00: OUT / 标准 / 设备
         └───────────────────── DATA0
[SYNC] D2            ; 设备 ACK

[SYNC] 69 00 10      ; 状态阶段: IN, 地址仍是 0（关键时序点！）
[SYNC] 4B 00 00      ; DATA1 ZLP
[SYNC] D2            ; 主机 ACK
```

**规范考点**：SET_ADDRESS 的地址**在状态阶段完成后**才生效（USB 2.0 §9.4.5）——
设备用旧地址 0 回完这个 ZLP，才把内部地址寄存器改成 5。固件在错误时机切地址是
"SET_ADDRESS 后枚举中断"的经典根因。

## 4. 事务三：GET_DESCRIPTOR(Device)，wLength=18（新地址复核）

```text
[SYNC] 2D 05 D0      ; SETUP, ADDR=5（已生效）, ENDP=0（CRC5 实算）
[SYNC] C3 80 06 00 01 00 00 12 00 E0 F4   ; GET_DESCRIPTOR Device, wLength=18
[SYNC] D2
[SYNC] 69 05 D0      ; IN, ADDR=5
[SYNC] 4B 12 01 00 02 00 00 00 40 41 23 01 00 00 01 01 02 00 01 EE E6
                     ; 与事务一完全相同的 18 字节（描述符是静态自我介绍）
[SYNC] D2
[SYNC] E1 05 D0      ; OUT（状态阶段）
[SYNC] 4B 00 00      ; DATA1 ZLP
[SYNC] D2
```

## 5. 事务四：GET_DESCRIPTOR(Configuration)，先要 9 字节头

```text
[SYNC] 2D 05 D0
[SYNC] C3 80 06 00 02 00 00 09 00 AE 04
         │        ─┬─       ─┬─
         │         │         └─ wLength = 9：只要头部
         │         └─────────── wValue = 0x0200：类型 0x02(配置), 索引 0
         └───────────────────── bRequest = 0x06
[SYNC] D2
[SYNC] 69 05 D0
[SYNC] 4B 09 02 22 00 01 01 00 A0 32 D9 6D
         └──── 9 字节 ────┘ ─┬─
                             └ CRC16 = D9 6D（实算）
[SYNC] D2
[SYNC] E1 05 D0
[SYNC] 4B 00 00
[SYNC] D2
```

9 字节配置描述符头逐字段：

| 字节 | 值 | 字段 | 解释 |
|---|---|---|---|
| 0 | `09` | bLength | 配置描述符头固定 9 字节 |
| 1 | `02` | bDescriptorType | 配置 |
| 2~3 | `22 00` | **wTotalLength** | 0x0022 = **34 字节**：配置9+接口9+HID9+端点7（自洽！下一步按这个数读全长） |
| 4 | `01` | bNumInterfaces | 1 个接口 |
| 5 | `01` | bConfigurationValue | SET_CONFIGURATION 的参数值 = 1 |
| 6 | `00` | iConfiguration | 无配置字符串 |
| 7 | `A0` | bmAttributes | bit7=1(必备) + bit5=1 支持远程唤醒（鼠标典型） |
| 8 | `32` | bMaxPower | 0x32×2 = **100 mA**（单位是 2mA，常被乘错的字段） |

## 6. 事务五：GET_DESCRIPTOR(Configuration)，全长 34 字节

```text
[SYNC] 2D 05 D0
[SYNC] C3 80 06 00 02 00 00 22 00 B0 F4   ; wLength = 0x0022 = 34（上一步拿到的 wTotalLength）
[SYNC] D2
[SYNC] 69 05 D0
[SYNC] 4B 09 02 22 00 01 01 00 A0 32
         09 04 00 00 01 03 01 02 00
         09 21 11 01 00 01 22 5B 00
         07 05 81 03 08 00 01
         E8 AF                            ; CRC16 = E8 AF（实算）
[SYNC] D2
[SYNC] E1 05 D0
[SYNC] 4B 00 00
[SYNC] D2
```

34 字节 = 配置(9) + 接口(9) + HID(9) + 端点(7)，解析：

```text
09 02 22 00 01 01 00 A0 32   配置描述符（同上）
09 04 00 00 01 03 01 02 00   接口描述符
   │  │  ─┬─ │  │  │  │  └ iInterface=0
   │  │   │  │  │  │  └─── bInterfaceProtocol=2 (鼠标)
   │  │   │  │  │  └────── bInterfaceSubClass=1 (Boot 协议 → BIOS 可用)
   │  │   │  │  └───────── bInterfaceClass=0x03 → HID！主机据此加载 HID 类驱动
   │  │   │  └──────────── bNumEndpoints=1（与下文端点数自洽）
   │  │   └─────────────── bAlternateSetting=0
   │  └─────────────────── bInterfaceNumber=0
   └────────────────────── bLength=9, bDescriptorType=0x04
09 21 11 01 00 01 22 5B 00   类特定 HID 描述符
   │     ─┬─ │  │  ─┬─
   │      │  │  │  └ wDescriptorLength=0x005B=91（报告描述符长，见附录）
   │      │  │  └─── bNumDescriptors=1
   │      │  └────── bCountryCode=0
   │      └───────── bcdHID=0x0111（HID 1.11, 小端）
   └──────────────── bLength=9, bDescriptorType=0x21
07 05 81 03 08 00 01         端点描述符
   │  │  │  │  ─┬─ └ bInterval=1 → 每 1ms 轮询一次（1000 Hz）
   │  │  │  │   └─── wMaxPacketSize=0x0008=8 字节
   │  │  │  └─────── bmAttributes=0x03 → 中断端点
   │  │  └────────── bEndpointAddress=0x81 → IN 方向, 端点号 1
   │  └───────────── bDescriptorType=0x05
   └──────────────── bLength=7
```

主机此刻完成"带宽预算"：EP1 IN 中断端点每 1ms 预留一次事务机会（见
[02-中断IN轮询.md](02-中断IN轮询.md) 实际轮询包流）。

## 7. 事务六：GET_DESCRIPTOR(String 0) — 语言 ID

```text
[SYNC] 2D 05 D0
[SYNC] C3 80 06 00 03 00 00 04 00 97 54   ; 类型 0x03(字符串), 索引 0 → LANGID 表
[SYNC] D2
[SYNC] 69 05 D0
[SYNC] 4B 04 03 09 04 09 78               ; bLength=4, 类型=3, LANGID=0x0409(美式英语, 小端)
[SYNC] D2
[SYNC] E1 05 D0
[SYNC] 4B 00 00
[SYNC] D2
```

随后主机按需读字符串 1/2（UTF-16LE，本文设备身份均为**示意值**）：

```text
[SYNC] C3 80 06 01 03 09 04 10 00 DB D8   ; 索引1, LANGID=0x0409, wLength=0x10
[SYNC] 4B 10 03 55 00 53 00 42 00 4C 00 61 00 62 00 73 00 0B D1
          └── "USBLabs" 的 UTF-16LE ──┘
[SYNC] C3 80 06 02 03 09 04 14 00 D9 2B   ; 索引2, wLength=0x14
[SYNC] 4B 14 03 4C 00 61 00 62 00 20 00 4D 00 6F 00 75 00 73 00 65 00 9E 62
          └── "Lab Mouse" ──┘
```

## 8. 事务七：SET_CONFIGURATION(1) — 上线

```text
[SYNC] 2D 05 D0
[SYNC] C3 00 09 01 00 00 00 00 00 27 25
         │  │  ─┬─
         │  │   └ wValue = 0x0001 → 配置值 1（0 = 去配置）
         │  └──── bRequest = 0x09 SET_CONFIGURATION
         └─────── bmRequestType = 0x00（OUT/标准/设备）
[SYNC] D2            ; 无数据阶段（wLength=0）→ 直接收尾
[SYNC] 69 05 D0      ; 状态阶段: IN
[SYNC] 4B 00 00      ; DATA1 ZLP → 设备进入 Configured 状态
[SYNC] D2
```

**枚举到此结束**：设备点亮"配置完成"，HID 类驱动开始接管——随后会以**类特定请求**
（bmRequestType=0x81）读 91 字节报告描述符（见附录），并开始按 bInterval 轮询 EP1
（[02-中断IN轮询.md](02-中断IN轮询.md)）。

## 9. usbmon 视角对照（同一序列的 URB 级样子）

软件抓包看不到 token/握手，只看到成对的 submit/complete：

```text
# sudo tshark -i usbmon2 -Y "usb.device_address==0 || usb.device_address==5"
No. Info
1   GET DESCRIPTOR Device LEN=64        ← 事务一
2   GET DESCRIPTOR Resp DEVICE (18B)    ← 短包结束, URB 提前完成
3   SET ADDRESS 5
4   GET DESCRIPTOR Device LEN=18        ← 换地址复核
5   GET DESCRIPTOR CONFIGURATION LEN=9  ← 先拿总长
6   GET DESCRIPTOR CONFIGURATION LEN=34 ← 按全长取
7   GET DESCRIPTOR STRING 0 / 1 / 2
8   SET CONFIGURATION 1                 ← 上线
```

```text
[SYNC] C3 81 06 00 22 00 00 5B 00 D3 6F
         │  │  ─┬─     ─┬─
         │  │   │       └ wLength=0x5B=91
         │  │   └ wValue=0x2200: 类型 0x22(报告), 索引 0 —— 接收者变为接口
         │  └──── bRequest=0x06 GET_DESCRIPTOR
         └─────── bmRequestType=0x81: IN / 类(01) / 接口(00001)
[SYNC] 4B 05 01 09 02 A1 01 09 01 A1 00 05 09 19 01 29 03
         15 00 25 01 75 01 95 03 81 02 95 05 81 03
         05 01 09 30 09 31 15 81 25 7F 75 08 95 02 81 06
         09 38 15 81 25 7F 75 08 95 01 81 06 05 0C 0A 38 02
         15 81 25 7F 75 08 95 01 81 06 05 09 19 04 29 05
```
