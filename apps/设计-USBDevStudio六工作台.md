│ 描述符树   │ 字段编辑表单                │ 双视图(标签):        │

│   ▾ 配置1  │ bDeviceClass [0x00]        │ 0x12 0x01 0x00 0x02 │
│     ▾ If0 │ bMaxPacketSize0 [8▾]      │ …(选中字段高亮同闪)  │
│       ▾EP1│ iSerialNumber [3 ▾→字符串] │                     │

### 2.2 控件清单

| 控件 | 规格 |
|---|---|
| 真机 ▾ | 设备目录联动选设备；选中后 [⟲反编译] 可用（**真机 GET_DESCRIPTOR 链路归 MS2**——MS1 反编译源=二进制文件/模型 JSON） |
| ⟲反编译 | 控制传输读全套描述符→解析为模型；**未知/私有字段保留 raw 字节**（round-trip 幂等：模型→bin→模型 无损）；解析失败处=红节点+原始 HEX 附着 |
| ✓检查 | 跑 Linter 规则库→底部问题列表（规则 ID/严重度 ✗⚠ℹ/条款引用/修复建议/[跳转字段]）；点击行=树+表单+HEX 三处同步高亮 |
| 生成 ▾ | C 头文件(TinyUSB 0.15/0.17 模板▾——实际差异仅注释级，MS1 收敛为 TinyUsb/PlainArrays 两档) · 二进制 .bin · **下发虚拟 DUT**(W3 设备即时换描述符，**归 MS2**——依赖 usbsim 设备实例) · 全部(预览对话框+保存) |
| diff ▾ | 与真机比对 / 与工程内版本 / 打开两文件——左右双树字段级差异，顶部摘要"3 处差异: bcdUSB/EP1 地址/字符串 2" |
| 描述符树 | 节点=描述符块（设备/配置/接口/IAD/端点/HID+报告描述符逐 Item/DFU/BOS/字符串×语言）；右键：添加同级/添加子级(合法类型白名单)/复制/删除(删接口=危险确认)/上移下移 |
| 字段表单 | 每字段一行：字段名/控件(合法值=下拉，数值=带 min/max，字符串=跳转字符串表)/HEX 原值只读列；改动即校验+标脏● |
| 报告描述符子编辑器 | 逐 Item 行（Global/Local/Main 栈视图右侧显示当前栈状态——栈不平衡=即时红条） |
| Linter 规则库 | 数据驱动：`rules.json`（id/severity/条款/检测表达式/修复建议），首批 25 条（bcdUSB 合法值/字符串索引有效性/端点地址冲突/接口号连续/MaxPower/HID 报告栈平衡/wMaxPacketSize 非法值/配置总长一致…）；规则库可插件扩展 |

### 2.3 状态机

编辑中(脏●) → 检查通过(✓绿) → 生成(任意目标) ；检查未过仍可生成（黄条提示）；反编译覆盖未保存修改=确认对话框。

├────────────┬──────────────────────────────────┬───────────────┤

### 3.2 控件清单

| 控件 | 规格 |
|---|---|
| 模板 ▾ | 虚拟设备模板（数据非代码：HID 键盘/HID 复合/MSC 大盘/PD Sink/BLE HOGP…模板=描述符模型+行为参数包）；模板本身=插件扩展点。**MS2 实装=前两模板（键盘/复合），MSC/PD/BLE 归 MS3；内核=C++ 原生 vd_core（EP0 状态机+HID 报告流），Python usbsim 全协议桥接归后续** |
| ▶启动/⏹ | 启动=usbsim 设备实例化+管道服务监听；主机侧经 ustsvd.dll 连入（见 3.4）；⟲重置=状态机回 Attached、统计清零、场景回 ① |
| ⏸ 断点暂停 | 命中断点自动冻结：事件流定位命中行(⛔)+设备状态面板刷新+会出现 [▶继续][⏭下一事务(单步)] |
| 协议事件流 | 逐事务行：时间/方向(主机→设备 蓝/设备→主机 绿)/事务摘要/字节数；FAIL 检测(超时/错误)=红行；点击行=右侧详情逐字节+解析(W4 解析器共用) |
| 状态检查器 | 当前状态机态+迁移历史（Addressed←Default←…）·EP0 阶段·描述符缓存(点击→W2 打开该模型)·统计（包/NAK/STALL/CRC 错计数） |
| 断点管理 | [＋断点] 五类：on_control_request(bmRequestType/bRequest/wValue 匹配表单) · on_enum_step(N) · on_ep_xfer(EP,方向) · on_state(状态名) · on_error_count(N)；断点列表勾选启用 |
| 错误注入 | 六快捷钮即时注入 + [自定义…]（类型/参数/持续次数表单）；注入在事件流留紫色标记行 |
| 场景脚本 | .ustssim=事件表（触发条件/动作/断言 三列组），事件类型：等待(条件)·注入·断言(设备状态/主机行为)·延时·循环(×N)；[▶随设备启动自动执行]；脚本=纯文本可 diff 可入库 |
| 会话录制 | [⏺录制] 记全事件流→存 .uststrace（W4 可开） |

### 3.3 调试会话生命周期

启动设备(未连接) → 主机程序经 ustsvd 连入(状态: ●已连接 客户端 pid) → 交互/断点循环 → ⏹停止(客户端收到断开=模拟拔出,可测应用拔插处理=热插拔模拟的另一形态)。

### 3.4 主机对接（ustsvd.dll，技术诚实账）

| 档 | 形态 | 承诺 |
|---|---|---|
| MS2 | **客户端库重定向**：应用链接 ustsvd.dll（导出与 hidapi/WinUSB 同形 API 子集），内部走命名管道到 usbsim 设备。**MS2 实装=进程内直连（VdSession+附录 D 消息编解码齐备）；hidapi 形状 DLL 导出+命名管道传输归 MS3**（编解码接口不变） | 首批 hidapi 12 函数+WinUsb 8 函数，覆盖表公开；链接方式=改一个 include/链接库 |
| P2 评估 | 内核级虚拟总线（系统出现真设备节点） | 需驱动签名+大工程量，另立方案评审 |

管道 `\\.\pipe\USTS-Runner-<pid>` UTF-8 JSON-lines；信封 `{"v":1,"t":…,"ts":…,"pid":…,"payload":…}`；消息：plan_load(GUI→runner {plan,dut_sn,station,mock}) · plan_loaded(runner→GUI {steps[{idx,name,type}],backend}) · step_start({idx,name}) · step_progress({idx,measured,pct?}≥4Hz 节流) · step_result({idx,name,pass,measured,note}≡报告 steps[] 元素) · run_done({verdict,crashed,report_path,elapsed_ms,pass_n,total}) · cancel({} 2s 未退强杀) · log({level,mod,msg} WARN↑转发通知中心) · heartbeat(1s,失 3 拍=崩溃态)。
租赁：互斥量 `Global\USTS\dev\<sha1(实例路径)前16>`；旁路文件 %TEMP%\USTS\leases\<hash>.json={pid,holder,ts} 仅展示诊断,正确性只认互斥量；GUI 退出不释放 runner 租约。
版本：v1 字段只增不改；未知 t=丢弃+warn 计数(runner 侧忽略)；v 不识别=断管报错。
