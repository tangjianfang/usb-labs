# 上位机软件工程实施方案（Windows Win32/C++20 + macOS Swift/AppKit）

> 版本: 1.0（2026-09-05）· 本文是 USB-Labs 上位机应用的权威工程方案。
> 原则: **高性能（重叠 I/O + QPC 高精度计时 + 无锁日志）、稳定（RAII/线程隔离/全面错误上报）、人性化交互（原生 UI 范式/DPI 感知/键盘可达）**。

## 1. 目标与边界

| 项 | 内容 |
|---|---|
| 产品形态 | 产线/实验室 USB 测试上位机（测试计划执行 → 量化判定 → JSON 报告 → MES 退出码） |
| Windows | Win32 API + Common Controls v6，C++20（VS2022 17.x），x64，Unicode，/W4，PerMonitorV2 DPI |
| macOS | Swift 5.9 + AppKit（native NSWindow/NSTableView），IOKit USB/HID |
| 依赖策略 | **零第三方依赖**（JSON 自研轻量 writer；不引 nlohmann/Qt） |
| 测试协议 | 枚举/描述符、HID（回报率/环回）、CDC 环回、MSC（SCSI 直通只读校验，写测试需确认）、PD 遥测 |

## 2. 架构（模块视图）

```
┌─────────────────────────── UI 层（平台原生） ───────────────────────────┐
│ Windows: main.cpp + MainWindow(Win32)  │ macOS: AppDelegate(AppKit)    │
│ 职责: 控件、DPI、消息泵、把引擎事件渲染到控件                              │
└───────────────△────────────────────────────────△───────────────────────┘
        WM_APP* 消息/回调                协议/委托回调
┌───────────────┴────────────────────────────────┴───────────────────────┐
│ 引擎层（可独立于 UI 的核心库）                                            │
│  TestEngine(工作线程): 执行 TestPlan → Step → 判定 → Report(JSON)        │
│  LogQueue(无锁单写多读): 引擎→UI 的事件流                                 │
└───────────────△────────────────────────────────△───────────────────────┘
┌───────────────┴────────────────────────────────┴───────────────────────┐
│ 设备访问层                                                               │
│ Win: DeviceEnumerator(CfgMgr32/SetupDi) · HidPort(hid.dll+Overlapped)    │
│      SerialPort(CreateFile COM) · MscScsi(IOCTL_SCSI_PASS_THROUGH_DIRECT)│
│      WinUsbPort(可选, 控制传输)                                           │
│ mac: IOKitScanner(IOServiceMatching) · IOHIDMonitor · ProbedProperties   │
└─────────────────────────────────────────────────────────────────────────┘
```

分层规则：**设备访问层不得包含 UI 类型**；引擎层通过回调/消息向上通知；UI 层只消费事件。

## 3. 线程模型

| 线程 | 职责 | 通信 |
|---|---|---|
| UI 线程 | 消息泵 + 控件更新 | 消费引擎投递的事件 |
| 引擎线程（每测试一个，std::jthread） | 顺序执行步骤、计时、判定 | 完成后投递完成事件；步骤级事件经 LogQueue |
| I/O | 全部重叠（OVERLAPPED + 事件）或平台异步 | 超时由引擎控制 |

规则：UI 线程禁止阻塞 I/O；引擎线程禁止触碰 HWND/NSView；日志队列容量上限+丢弃计数（防内存膨胀）；所有句柄 RAII 封装。

## 4. 测试步骤与判定（与 tools/usbtest 的 JSON 计划同构）

| 步骤类型 | Windows 实现 | macOS 实现 | 判定 |
|---|---|---|---|
| enumerate | CfgMgr32 枚举 + VID/PID/名称 | IOKit 扫描 | 找到且接口数符合 |
| descriptor_check | HIDP_CAPS/WinUsb_GetDescriptor | IOHIDDevice 属性 | 与白名单一致 |
| hid_polling_rate | Overlapped ReadFile + QPC 直方图 | IOHIDReportCallback 时间戳 | ≥ min_hz |
| hid_output_write | HidD_SetOutputReport / WriteFile | IOHIDDevice setReport | 写成功 + 人工/光敏确认项 |
| serial_loopback | ReadFile/WriteFile 模式比对 | 同 | 字节级一致 |
| line_coding | （可选 WinUSB 控制传输） | — | 回读一致 |
| msc_read_verify | SCSI PASS-THROUGH DIRECT READ10 + 模式比对 | （授权场景, 概要） | 数据一致 |
| pd_telemetry | 串口 key=value 采集 | 同 | 字段齐全且在限内 |

报告 JSON 结构与 tools/usbtest 完全一致（plan/station/dut_sn/verdict/steps[]），可直接进 MES。

## 5. 错误处理策略

- Win32 一律检查 BOOL/HANDLE 失败，失败时记录 `GetLastError()` 与上下文；
- 引擎步骤级异常不中断整站（步骤置 FAIL 继续），与 Python 版口径一致；
- 设备中途拔出：OVERLAPPED 返回 ERROR_OPERATION_ABORTED/ERROR_GEN_FAILURE → 步骤 FAIL + 触发重扫提示；
- 报告写盘失败 → 降级输出到 %TEMP% 并在 UI 顶部告警。

## 6. 人性化交互清单

- PerMonitorV2 DPI 感知 + 系统主题文字色；
- 快捷键：F5 扫描、Ctrl+R 运行测试、Ctrl+S 导出报告；
- 日志等宽字体 + 时间戳 + 级别着色（信息/告警/失败）；
- 测试进行中禁用危险操作、按钮状态机明确（空闲/运行/完成/失败）；
- 全部确认框可关闭"再次询问"（记住选择于 %APPDATA%）。

## 7. 构建与里程碑

| 里程碑 | 内容 | 验收 |
|---|---|---|
| M1 | Windows: 枚举 + HID 回报率 + 日志 | 真机枚举 + ≥900Hz 判定 |
| M2 | Windows: CDC 环回 + MSC 只读校验 + JSON 报告 | 报告可被 MES 消费 |
| M3 | macOS: 扫描 + HID + 报告 | 真机与 Windows 结论一致 |
| M4 | 双平台测试计划互通（同一 JSON） | 计划文件互换可跑 |

构建：Windows 用 VS2022 打开 `CMakeLists.txt`（或生成 sln）；macOS 用 `swift build` / Xcode。
