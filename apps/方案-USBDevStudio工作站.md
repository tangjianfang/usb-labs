# 方案 · USB DevStudio 全栈工作站（总纲 v2）

> 状态: **approved（六工作台骨架 + MS0→MS2 双引擎先行，均经用户确认）** · 2026-09-10
> 定位演进：demo（≈1% 基线）→ 统一工程软件（v1 方案，已被超越）→ **全栈 USB IDE 工作站**。
> 一句话：**把"开发一个 USB 设备"当作一个工程打开**——像 IDE 之于写代码，DevStudio 之于造 USB 设备：硬件↔固件↔描述符↔主机程序↔测试↔产线，一个工程全装下。
> 控件级详设见 [设计-USBDevStudio六工作台.md](设计-USBDevStudio六工作台.md)。

## 一、已拍板决策（全部用户确认）

| 决策点 | 结论 |
|---|---|
| 产品形态 | **全栈 USB IDE 工作站**（六工作台 × 四视角，产品名 USB DevStudio，由 USBTestStudio 演进） |
| 功能策略 | **不砍**：v1 的 129 项全保留归位，新增工作站级能力，总量 ~160 项 |
| 平台 / 技术栈 | Windows 先行 · 纯 Win32/C++20 零第三方依赖（面板注册表 + token 单源延续） |
| 进程模型 | 混合容器：GUI 主进程 + 功能 DLL + runner 子进程 + 外联子进程（不变） |
| 建造顺序 | MS0 壳 → **MS1 描述符编译器 + MS2 虚拟调试器（双引擎先行）** → MS3 测试台 → MS4 追踪台 → MS5+ 滚动 |
| 专业性标准 | 每工作台配一台"别人没有的引擎"（编译器/调试器/DSL/CI 级），包装器模式禁止 |

## 二、六工作台与四视角

| 工作台 | 引擎（免费世界空白/壁垒） | 替代的工作流 |
|---|---|---|
| **W1 项目台** | 工程模型 `.ustsproj` + 模板库（7 个 lab 即 7 个官方模板）+ 设备目录/绑定诊断/能力档案 | 散落的资料、工具、上下文 |
| **W2 描述符台** | **描述符编译器**：模型 ⇄ 二进制 ⇄ C(TinyUSB) 三向；真机反编译→编辑→Linter(规则引规范条款)→生成/下发/diff | 手写 usb_descriptors.c 数组；只读式查看工具 |
| **W3 虚拟调试器** | **usbsim IDE 化**：设备模板+场景脚本+协议断点+状态机单步+错误注入（STALL/NAK/坏描述符/掉电） | 上位机只能真板测、错误路径物理造不出；Ellisys 仿真 ¥3 万级 |
| **W4 协议追踪台** | **过滤 DSL**+统计引擎：会话/USBPcap 统一时间线、显示过滤语言、着色、带宽统计、捕获 diff | 滚动日志看不了协议；Wireshark 无设备上下文 |
| **W5 测试台** | **设备回归 CI**：Test Explorer + 双后端（虚拟=每次提交/真机=nightly）+ Pipeline 工作流(.ustsflow: 烧录→验证→测试→报告链) | "固件改了没人重新验证协议" |
| **W6 产线台** | 执行视图/大屏/MES/报告/良率（v1 M2/M5/M6 归位） | 一次性产测脚本 |

**视角系统**（同一壳，一键切换布局与可见面板）：`开发`（W1+W2+W3）· `调试`（W3+W4+控制台）· `测试`（W5+历史）· `产线`（W6 大屏/执行）。
**平台服务**：命令面板 Ctrl+K · 知识服务（字段/错误/UUID 悬停→USBTree 规范条款，"USB 的 IntelliSense"）· 脚本控制台 · 插件 ABI（面板/步骤/解析器/设备模板四类扩展点）· 设置/更新/崩溃/主题。

## 六、架构（混合容器不变，引擎升格）

```
USBDevStudio.exe ── GUI 主进程(零依赖): 视角系统+命令面板+面板注册表
 ├ core.lib       framework/usb/engine/report/parser(现有资产平移)
 ├ 引擎层:  desc_compiler.lib(W2 三向+Linter)  ·  usbsim(W3 内核, 升格)  ·
 │          trace_dsl.lib(W4 过滤/统计)  ·  pipeline(W5)
 ├ 功能 DLL:  uvc_preview / uac_measure / ble_panel / pcap_reader …
 ├ ustsvd.dll   虚拟 DUT 客户端库(重定向 hidapi/WinUSB 调用→管道→usbsim)
usts_runner.exe ── 产测/测试执行子进程(双后端: 真机=core.usb / 虚拟=usbsim)
外联子进程 ── dfu-util/USBPcap/USB3CV/f3/UsbTreeView/MUTT
IPC: 命名管道 JSON-lines(v1 附录 D 信封延续+调试器消息扩展) · 设备租赁表
```

**W3 主机对接的技术诚实账**：虚拟设备对主机程序的呈现分三档——MS2 用 `ustsvd.dll` 客户端库（应用链接它，API 形状同 hidapi/WinUSB 子集，内部走管道到 usbsim；零驱动、免签名）；内核级虚拟总线驱动（系统里出现真设备节点）= P2 评估项（需测试签名/驱动签名，工程量大）。

## 八、风险（v1 风险表继承 + 工作站新增）

| 风险 | 等级 | 缓解 |
|---|---|---|
| Win32 自绘面板框架 | 高(唯一) | 预设布局+面板注册表先行；退路=主窗口分栏 |
| **ustsvd 重定向库的 API 覆盖度** | 中高 | MS2 首批只承诺 hidapi 常用 12 函数+WinUSB 8 函数；覆盖表公开；内核驱动路径保留为 P2 |
| **usbsim 设备模型扩展量**（模板×3 需补键盘复合+PD 行为） | 中 | 内核已有 HID/MSC/PD 骨架；模板=数据不是代码 |
| Linter 规则库是内容工程 | 中 | 首批 25 条(描述符硬规则)+USBTree 条款映射；逐里程碑扩 |
| USBPcap 依赖外部安装 | 低 | 外联探测+安装引导；无它则 W4 退化为会话级捕获 |
| USB3CV 接管 xHCI | 中 | 强警示+专用机建议 |
| 代码签名 | 低/预算 | EV 证书待拍板 |
| 体量管控（~160 项） | 中 | 里程碑竖切+每期 DoD；功能大全即冻结清单，防蔓延 |
