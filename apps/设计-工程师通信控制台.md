# EP-4 · 工程师通信控制台（Communication Console）设计方案

> 状态: **approved（用户指令触发，1.4.0 协议 (f)）** · 目标版本: v0.3 核心形态
> 一句话: 让工程师"三秒内找到设备、一键打开会话、像串口助手一样收发、协议自动解析"。

## 一、解决的根本痛点

| 痛点 | 现状 | 本设计 |
|---|---|---|
| 设备难找 | 枚举后一长串 path 人工肉眼找 | **即时过滤**：一个搜索框匹配 名称/VID:PID/协议/路径子串（如输 `2341` 或 `key` 或 `HID`），列表实时收敛；双击即开会话 |
| 通信方式割裂 | 每种协议各写一套工具 | **统一会话模型**：HID / 串口 / WinUSB 批量 / MSC 四种通道同一套收发交互 |
| 发送不便 | 无 | 发送框（Hex/ASCII 自动识别切换）+ **周期发送** + **发送历史**回选 + 常用命令快捷栏 |
| 接收不便 | 无 | 滚动接收区：暂停/清屏、Hex↔ASCII 双视图切换、时间戳、落盘存档 |
| 解析不便 | 无 | **协议解析面板**：按设备协议自动解码（HID 报告→修饰键/键码/坐标；PD→消息字段；MSC→CDB/CSW），原始视图与解析视图并列 |

## 三、统一通信通道抽象（架构核心）

```
IChannel（抽象接口）
 ├─ open/close、send(bytes)、on_receive(cb)、set_timeout、描述信息
 ├─ HidChannel    : 路径打开(hid.dll/CreateFile)、读报告、写报告、SetOutputReport
 ├─ SerialChannel : COM 打开、DCB 配置、读写（同串口助手）
 ├─ WinUsbChannel : 管道读写（批量 IN/OUT 端点选择，需 WinUSB 驱动设备）
 └─ MscChannel    : 卷句柄 + SCSI 直通（INQUIRY/READ/WRITE 封装）
解析器 IParser（与通道正交，可插拔）:
 ├─ HidReportParser（按 Usage Page 输出键位/坐标/消费码名称）
 ├─ AsciiParser（默认文本视图）
 ├─ BotParser（CBW/CSW/数据段标注）
 └─ PdParser（Header 位域/PDO/RDO 展开）
```

工程意义：这套 `IChannel` 抽象同时也是自动测试引擎的传输层——**调试台与产测引擎共用同一套通道实现**，测试工程师在控制台验证过的收发序列可直接固化为自动测试步骤。

## 四、交互细节（易用性清单）

1. 过滤即所见：搜索框输入任何子串（不区分大小写）实时过滤，支持多关键词空格分隔（AND）；协议复选框二次过滤；
2. 双击设备 → 按协议自动建会话标签（HID→报告会话，串口→终端会话）；`[+]` 可手动建第二会话；
3. 发送框智能识别：仅含 `0-9A-Fa-f 空格` → Hex 模式（奇数字节自动补前导 0）；含其他字符 → ASCII 模式；可手动锁定；
4. 周期发送：勾选后按设定间隔（100ms~60s）重复发送，运行指示灯闪烁；
5. 发送历史：最近 50 条，上下键回选；快捷栏可保存常用命令（持久化到 %APPDATA%）；
6. 接收区：暂停滚动（继续后台收）、自动滚动开关、时间戳（相对/绝对）、超大流量自动降采样显示（不丢原始归档）；
7. 解析面板默认跟随设备协议打开；解析字段悬停显示知识库对应条目链接。

## 五、实施切分

| 切片 | 内容 | 验收 |
|---|---|---|
| S1 通道层 | IChannel + HidChannel + SerialChannel（Win32） | 真机 HID/串口收发 |
| S2 设备发现 | 枚举 + 即时过滤表格 + 双击开会话 | 输关键词 3 秒定位目标 |
| S3 会话台 | 标签化多会话 + 收发区 + 历史/周期 | Hex/ASCII 双模式收发 |
| S4 解析面板 | HidReportParser + AsciiParser | HID 报告自动解码 |
| S5 WinUSB/MSC 通道 | 批量管道 + SCSI 直通封装 | 对 U 盘读扇区 |
| S6 PD 面板 | 遥测监视（依赖 Lab5 遥测契约固件） | 与固件联调 |

平台顺序：Windows 先行（本机可编译验证）；macOS 版按同设计用 AppKit+IOKit 复刻（挂起状态保留）。
