## 1. ble_hid.c：HOGP 服务注册要点

### 1.1 要点清单

1. **Report Map（0x2A4B）直接引用共享描述符**：`bt_hids`（NCS 的 HOGP 服务实现）以初始化参数传入报告映射表，把 USB 报告描述符字节流原样填入。
2. **Report 特征值（0x2A4D）+ Report Reference 描述符（0x2908）**：每个报告一个特征值实例，描述符内容 = (Report ID, 类型)，类型：1=Input 2=Output 3=Feature。键盘 Input 报告用 Notify 上报，LED Output 报告由主机 Write。
3. **Boot 协议特征**：HOGP 定义了 Boot Keyboard/Mouse Input Report（0x2A22/0x2A33），供主机在无驱动阶段使用；PC 场景可只实现 Report 模式，示例里两者都有。
4. **BAS 电池服务（0x180F）**：笔记本系统会拿它显示电量；商业键盘必备，漏了会被当"未知电量"。
5. **协议模式（0x2A4E）**：Report/Boot 切换开关，默认 Report。
6. 发送路径：按键事件 → 组标准 HID 报告（与 USB 侧同一函数）→ `bt_hids_report_send()` 发 ATT Notification（opcode 0x1B）。

### 1.2 骨架（示意，非完整可编译）

```c
/* ble_hid.c —— 基于 NCS <bluetooth/services/hids.h> 集成，API 名以所装版本为准 */
#include <zephyr/bluetooth/bluetooth.h>
#include <bluetooth/services/hids.h>
#include "report_desc.h"   /* ★ 共享 HID 报告描述符，USB/HOGP 同源 */

static const uint8_t report_map[] = HID_REPORT_DESC; /* 与 usb_hid.c 同一份字节 */

static struct bt_hids_rep_map rep_map = {
    .rep_map     = report_map,
    .rep_map_size = sizeof(report_map),
};
/* input 报告实例：ID=1 键盘 / ID=2 系统控制 / ID=3 消费类（多媒体键）…… */
static struct bt_hids_inp_rep inp_reps[] = {
    HIDS_INPUT_REP_INIT(0x01), HIDS_INPUT_REP_INIT(0x02), HIDS_INPUT_REP_INIT(0x03),
};
static struct bt_hids_outp_rep outp_reps[] = { HIDS_OUTPUT_REP_INIT(0x01) }; /* LED */

int ble_hid_init(void)
{
    struct bt_hids_init_param init = { 0 };
    init.info_parser.rep_map      = rep_map;
    init.inp_rep_group.cnt        = ARRAY_SIZE(inp_reps);
    init.inp_rep_group.reps       = inp_reps;
    init.outp_rep_group.cnt       = ARRAY_SIZE(outp_reps);
    init.outp_rep_group.reps      = outp_reps;
    init.evt_cb                   = hids_evt_cb;   /* 连接/订阅/写 LED 回调 */
    return bt_hids_init(&init);
}

int ble_hid_send_keyboard(const uint8_t rep[8])   /* 与 USB 侧共用 keyboard.c 输出 */
{
    return bt_hids_report_send(&hids_obj, conn_by_slot, rep, sizeof(rep));
}
```

## 2. link_2g4.c：dongle 私有 2.4G 链路的两条路线

| 路线 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **A. 私有协议（ESB）** | 键盘 PTX ↔ dongle PRX，Nordic ESB 库；自定封包（前导/地址/载荷+CRC），可加 AES 加密 | 延迟与占空比完全自控，dongle 不占系统蓝牙栈 | 自研配对/跳频/重传策略 |
| **B. dongle 即 BLE Central** | dongle 与键盘之间也走 BLE 连接（白名单绑定），对 PC 仍是 USB HID | 配对/加密/重传全复用蓝牙栈，省一份私有协议 | 延迟受连接间隔下限（7.5ms）与协议栈调度约束 |

商业 dongle 键鼠（罗技 Unifying 类）普遍是路线 A 的私有 2.4G + AES；对学习者，**先做 B 再升级 A** 是平滑路径（B 的配对策略与蓝牙槽位完全共用）。两路线下 `usb_hid.c` 收到的都是**标准 HID 报告**，下游完全一致。

ESB 侧要点（路线 A）：设备地址 = 出厂唯一（见 §4）；跳频表私有但避开 WiFi 主信道是常规做法；重传与 ACK 由 ESB 库提供；** dongle 断电重插后需在数秒内完成"再同步"**（监听期拉长 + 键盘侧周期性 hello 包），这是售后"拔插 dongle 要重配对"投诉的直接对策。

## 3. usb_hid.c：dongle 把 2.4G 收包转 USB HID 报告

```c
/* usb_hid.c —— 基于 Zephyr USB HID 类（<zephyr/usb/class/usb_hid.h>，API 以版本为准） */
static const uint8_t hid_report_desc[] = HID_REPORT_DESC;   /* ★ 同一份描述符 */

static const struct hid_device_ops hid_ops = {
    .get_report = get_report_cb,   /* 主机 GET_DESCRIPTOR(HID Report) → 返回描述符 */
    .set_report = set_report_cb,   /* LED 输出报告：喂给 link_2g4 下行发回键盘 */
    .int_in_ready = int_in_ready_cb,
};

/* 收到 2.4G 标准HID报告（bridge.c 已剥私有头）→ 中断端点上报 */
void on_radio_report(const uint8_t *rep, uint8_t len)
{
    hid_int_ep_write(hid_dev, rep, len, NULL);  /* 主机 1ms 轮询即取走 */
}
```

要点：

1. **dongle 对 PC 是零驱动标准 HID**：VID/PID/字符串描述符做厂商区分即可；`bInterfaceProtocol` 用键盘 1 / 鼠标 2。
2. 上行（按键→PC）与下行（LED/caps lock 状态→键盘）都要通；下行丢了会表现为"指示灯不同步"。
3. USB 挂起（suspend）：PC 睡眠后 dongle 应停发射省电，由 SET_PROTOCOL/挂起事件驱动。

## 4. pair.c：配对按钮与白名单策略

策略（商业键鼠通行做法的共识化描述）：

| 事件 | 行为 |
|---|---|
| 短按配对键 | 当前通道进入快速广播（20–30ms 间隔，30s），等待主机配对 |
| 长按 3s | **清除本通道绑定**（`bt_unpair()`），重新进入配对；防"旧绑定残留导致连不上"的售后 |
| 配对成功 | 对端进入**白名单**（bond 存 settings/FDS/Flash），此后仅接受白名单内主机连接 |
| 重连 | 优先 **定向广播（ADV_DIRECT_IND，对白名单内地址）**，秒连；超时（数秒）回落慢速非定向广播省电 |
| dongle 通道 | 配对 = 与 dongle 交换地址/密钥（ESB 路线）或标准 BLE 配对（路线 B），同样落白名单 |

实现锚点：绑定存储用 settings 子系统（`CONFIG_BT_SETTINGS` + Flash）；地址用 Nordic FICR 出厂 `DEVICEADDR`（随机静态地址，量产免烧自定义 MAC）；多通道 = 白名单三份槽位（见 [../experience.md](../experience.md) §3）。

## 5. 集成点核对清单

- [ ] `report_desc.c` 单一来源，USB 与 HOGP 均引用，描述符带 Report ID
- [ ] 键盘报告生成函数与通道层解耦（同一报告对象，通道选择只决定"发给谁"）
- [ ] BAS 电池服务接入 ADC 电压-电量曲线（CR2032 放电曲线平缓，低电量告警阈值要实测）
- [ ] DC/DC 使能（prj.conf：`CONFIG_BOARD_ENABLE_DCDC=y` 类配置）与低频时钟选外部晶体
- [ ] 绑定清除入口（长按）真机验证：清完必须能立刻重新配对
- [ ] dongle 掉电重插再同步 < 5s，无需用户重新配对
