# 硬件设计要点：UVC 摄像头 + UAC 麦克风（教学级 MCU / 商业级 SoC）

> 本文覆盖 Lab4 的硬件层设计要点：并行口与 MIPI 布线、sensor 时钟与 PLL、I2S 麦克风布局、铝壳散热，以及一条完整的 **UVC 带宽预算计算示例**（1280×720@30 MJPEG，含 HS 同步端点包长的正确填法）。

## 1. 两条硬件路线的拓扑总览

```
教学级（MCU）：                          商业级（SoC）：
OV5640 ──DVP并行口──▶ STM32H743          MIPI sensor ──CSI-2──▶ SoC(片上ISP)
        (JPEG直出)    DCMI  ▲PCLK/HS/VS        (RAW10)        │
                      OTG_HS+USB3300 ──USB──┐  ES8311 codec ◀─I2S/TDM─┘
INMP441 ──I2S──▶ SAI/I2S 外设 ──────────────┤  USB2 HS PHY ──USB──▶ PC
                                            ▼
                                           PC（UVC+UAC 复合设备）
```

教学级关键点：**JPEG 编码发生在 OV5640 sensor 内部**（MCU 无编码器），MCU 只做搬运与 UVC 打包——这是 MCU 方案能"低成本出 MJPEG"的根本原因，也是它画质/码率不可调的根本限制。

## 2. DVP 并行口（DCMI）布线要点

OV5640 的 DVP 接口信号：`PCLK`（像素时钟，输出）、`VSYNC`、`HREF`、`D0–D7`（8 位数据）、`XCLK`（输入，MCU 给 sensor 的 24MHz 主时钟）、`SIOC/SIOD`（SCCB/I2C 配置）。

- **速率现实**：JPEG 模式下 PCLK 典型 24–48MHz（分辨率/帧率相关，最高可到 96MHz 量级）。按 4 层板走线不按"低速排线"处理；
- `PCLK/VSYNC/HREF/D[7:0]` 建议各串 **22–33Ω** 阻尼电阻，抑制振铃；过孔少、换层时伴回流地过孔；
- **等长不苛刻**（并行口对时序裕量大），但 PCLK 与数据组长度差建议控制在 ±10mm 内；FPC 排线尽量短（<8cm）并远离 USB 差分对；
- MCU 侧 DCMI 依赖 DMA 搬 FIFO：**DMA 使用 AHB 总线矩阵带宽**，同时跑 USB OTG HS DMA 时要核对总线争用（教学级实测中"图像撕裂"常见根因是 DMA 带宽不足而非布线）；
- sensor 电源 2.8V（模拟）/1.8V（IO）/1.5V（内核，模组常自带 LDO）：模组购买时确认供电架构，直接用模组自含 LDO 最省事。

## 3. MIPI CSI-2 布线要点（商业级）

- 数据对/时钟对 **100Ω 差分阻抗**，对内等长 ±5mil（0.127mm），对间长度差可放宽；
- 完整参考平面（相邻层不离地），换层配回流地过孔；FPC 长度按核心板手册上限（常见 ≤15cm）；
- sensor 与 SoC 间无需重定时器，但 2-lane 起；RAW10 @1080p30 约 0.5Gbps/lane 量级——这是 SoC 方案高帧率低延迟的物理基础；
- MIPI 与 USB/天线区域保持 3W 间距，避免会议设备"插 USB 后 MIPI 误码"的组合干扰。

## 4. Sensor 时钟与 PLL

- **XCLK 来源**：MCU MCO 输出 24MHz（教学级常用）或模组自带晶振。MCO 输出加串阻并短走线——它本质是一路 24MHz 干扰源；
- **OV5640 内部 PLL**：XCLK 经内部 PLL 倍频到系统时钟（典型 84–168MHz 区间，视分辨率/帧率配置），再分频出 PCLK。改分辨率/帧率时改的是 sensor 寄存器组（DVP 时序随之变化），MCU 端 DCMI 无需重配时钟；
- **JPEG 直出模式**：sensor 内编码后数据量骤降，PCLK 占空可被拉伸——DCMI 采样仍以 PCLK 为准，无需 MCU 侧 PLL；
- EMI 提示：24MHz XCLK 与 PCLK 谐波会落在 FM/手机频段，会议产品做 FCC/CE 时这两处是整改重灾区（铝壳此时兼作屏蔽）。

## 5. I2S 麦克风布局（含"模拟地/数字地"的正确打开方式）

数字 MEMS 麦（INMP441/ICS-43434）输出的是 I2S 数字流，**没有模拟音频信号走线**，所以地处理的核心不是"音频模拟地"，而是**时钟回流完整性与 codec 模拟供电隔离**两件事：

- **SCK/WS/SD 短走线**（<5cm 理想），SCK 是 64×fs（48kHz 时 3.072MHz）方波：包地/邻近回流平面，禁止与 USB D+/D-、DCMI 并行长距离平行走线；
- **时钟抖动 = 音质**：I2S 时钟来自 MCU/SoC 的 SAI 外设，与 USB 时钟同源或不同源决定采样率漂移（见 [experience.md §4](../experience.md)）；给 MEMS 麦供电的 VDD 加磁珠+去耦，防止 USB 高速开关噪声耦合进麦的内部放大器（那才是真正的"模拟"环节）；
- **多麦阵列**（会议机）：麦间距 ≥ 数厘米按波束成形阵列设计，声孔与外壳配合密封，防串音与结构传声；
- **商业级用 codec（ES8311）时**：AVDD 单独 LDO 或磁珠隔离，AGND 与 DGND **单点连接**（网形混接反而引入环路），模拟麦偏置电阻远离 DCDC 电感；
- 麦克风开孔：外壳声孔对准麦声孔并留密封圈，"能听到但灵敏度差 10dB"多数是结构漏声不是电路问题。

## 6. 铝壳散热（商业级）

- SoC 方案整机功耗约 1–3W（含 sensor 与 codec），1080p H.264 机型偏上限；铝壳是天然散热器：芯片表面涂导热垫/导热硅脂（1–3 W/m·K）压接到壳内壁，壳体阳极氧化层导热差但对辐射散热与 EMI 屏蔽有利；
- 金属壳会屏蔽天线：内置 WiFi 的会议机需外置天线开窗，纯 USB 设备无此顾虑，反而**屏蔽是免费福利**（UVC 高速差分对外辐射更容易达标）；
- 结构验证：满帧率烤机 30 分钟，红外枪测芯片结温区域 ≤ 手册上限减 15°C 余量；铝壳接口开孔做去毛刺与接地簧片（壳体与 GND 单点搭接，避免" Floating shield "把地噪声带进音频地）。

## 7. UVC 带宽预算计算示例（核心）

**命题**：1280×720@30fps MJPEG，USB 2.0 高速同步端点，包长怎么填？

### 7.1 码率估算

- MJPEG 720p 单帧经验值：**30–110 KB**（画质/场景运动量相关，中位约 60 KB）；
- 取 60 KB/帧：60,000 B × 30fps = 1.8 MB/s ≈ **14.4 Mbit/s**；
- 每 USB 微帧（125µs）平均负载：14.4 Mbit/s ÷ 8000 微帧/s ≈ **1800 B/微帧**。

### 7.2 端点包长怎么填（wMaxPacketSize 的多事务编码）

HS 同步端点单事务上限 1024B/微帧；USB 2.0 允许"高带宽端点"每微帧 1–3 个事务，编码方式（易错点）：

| 每微帧有效字节 | 事务数 | wMaxPacketSize 字段值 = ((事务数-1)<<11) \| 1024 | 备注 |
|---|---|---|---|
| 1024 | 1 | 0x0400（1024） | MCU 方案典型上限 |
| 2048 | 2 | 0x0C00（十进制 3072，≠2048！） | 编码值≠字节数，抓包/描述符核对时易混 |
| 3072 | 3 | 0x1400（十进制 5120） | 商用 MJPEG 摄像头常见 |

对应地，固件在 Probe/Commit 里回报的 `dwMaxPayloadTransferSize` = 每微帧载荷预算（如 1024 或 3072），主机按它收包；MJPEG 载荷头（2–12 字节）**计入**该预算，分帧时数据切片 = 预算 − 头长。

### 7.3 结论与教学级预期

- **单事务 1024B/微帧 = 8.192 Mbit/s 上限**：装不下 60KB 帧的 720p30。教学级选项：
  - 降画质：平均帧 ≤34 KB（≈8.2 Mbit/s）可保 720p@30 名义值，实际波动会掉帧；
  - 降帧率：60KB 帧 → 实际 **15–25fps**（本 Lab 教学固件的诚实预期）；
  - 降分辨率：640×480@30（帧 15–25KB ≈ 3.6–6 Mbit/s）最稳；
- **多数 STM32（DWC2 OTG HS）工程上限为每微帧 1 事务**（高带宽模式支持度以参考手册与 errata 为准）——这就是"MCU 方案=低帧率"的物理根源，[README §2.2](../README.md) 的对比表由此而来；
- 商业方案：高带宽端点（3072B/微帧 = 24.6 Mbit/s）覆盖 720p30 中位画质；更高画质/1080p 常改用**批量传输**（采集卡路线，尽力而为但吞吐高）。

### 7.4 总线预算（多设备/Hub 场景）

- USB 2.0 规定每微帧最多 **80%** 时间给周期性传输（同步+中断）：480 Mbit/s × 0.8 × 125µs ≈ **6000 B/微帧**为全总线周期性预算；
- 一台 3072B/微帧 的 720p 摄像头占掉一半；**两台即接近打满 6000B 预算**——"一个 Hub 挂两三台摄像头开始掉帧"的数学根源（展开见 [experience.md §2](../experience.md)）；
- UAC 麦克风带宽可忽略：48kHz/16bit/单声道 = 96 B/ms（FS）≈ 0.77 Mbit/s；HS 下每微帧 12B（+异步抖动余量取 16B 足够）。

## 8. 设计检查清单

- [ ] DVP/MIPI 走线短、串阻齐、回流完整；FPC 长度在 sensor/核心板手册限值内；
- [ ] XCLK/PCLK 识别为干扰源：远离 USB 差分对与麦克风；
- [ ] I2S 三线短走线包地；codec 方案 AVDD/AGND 单点；MEMS 供电磁珠+去耦；
- [ ] USB 差分 90Ω、ESD 低结电容、VBUS 保险；
- [ ] 铝壳：导热垫压接、壳地单点搭接、开孔毛刺；烤机测温留余量；
- [ ] 描述符与硬件一致：HS/FS 双配置、`wMaxPacketSize` 多事务编码正确、`dwMaxPayloadTransferSize` 与包长闭环（与 [firmware/src/uvc_descriptors.c](../firmware/src/uvc_descriptors.c) 对照检查）。
